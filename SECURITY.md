# Security Policy

## Supported versions

Security fixes are applied to the latest release and to `main`. Older releases
may not receive backports; upgrade to the newest available version before
reporting an issue that is already fixed there.

## Reporting a vulnerability

Please report vulnerabilities through [GitHub private vulnerability
reporting](https://github.com/HenryDeGrasse/support-bundle-investigator/security/advisories/new).
Do not open a public issue with exploit details, credentials, customer data, or
a real support bundle. If private reporting is unavailable, open a
non-sensitive issue asking the maintainers for a private contact channel.

Include the affected version or commit, impact, minimal reproduction steps, and
any proposed mitigation. Use synthetic data and redact cluster names, tokens,
URLs, and other identifying information.

Particularly useful reports include archive extraction escapes or denial of
service, secret leakage, unsafe generated reports, dependency compromise, and
unexpected network transmission of bundle content.
