What I changed
- Fixed a telemetry accounting edge case in `src/investigators/ai-investigator.ts`:
  - if an LLM call succeeded and telemetry had already been recorded, but later response processing threw, the run could be double-counted as both a success and a failure.
  - I added a guard so fallback failure telemetry is only added when no per-call telemetry has been recorded yet.
- Added regression coverage in `src/investigators/__tests__/ai-investigator.test.ts`:
  - verifies post-call processing failures do not double-count AI call telemetry.

Assessment
- The step was largely implemented correctly already:
  - per-call latency/token/cost telemetry is captured in the LLM client
  - AI investigator aggregates it
  - pipeline writes `trace.aiSummary`
  - JSON report emits top-level `aiSummary`
- The only real issue I found was the double-counting edge case above; that is now fixed.
