## Plan Summary

I explored the full codebase structure and wrote a 15-step implementation plan covering three major areas:

### Evals (Steps 1–5)
1. **Expand golden expectations** to cover existing but untested `ghost-service` and `multi-namespace-retrieval` scenarios
2. **New scenarios**: `network-policy-deny` and `node-taint-memory-pressure` to exercise under-tested investigators
3. **Helm release failure** scenario to validate Helm parser coverage
4. **Eval scorecard** — a Markdown table + JSON reporter that formalizes the eval as a regression gate
5. **AI cassette eval** — replay-based golden test using pre-recorded synthetic LLM responses (no API keys needed)

### Observability (Steps 6–9, 14)
6. **Enrich trace.json** with seed counts, retrieval breakdowns, confidence stats, and hypothesis counters
7. **Per-finding provenance** — new `FindingProvenance` type tracking investigator source, seed, merge history, and confidence deltas
8. **AI cost/latency/model summary** — instrument `LLMClient` for per-call timing + token usage, aggregate in trace
9. **`--debug` CLI flag** — emits enriched trace + provenance files
14. **Wire diagnostics into reports** — JSON and Markdown reports gain a diagnostics section

### Robustness (Steps 10–13)
10. **Corrupt/partial bundle tests** — random bytes, truncated archives, empty bundles, malformed YAML, binary files
11. **Oversized bundle guard** — `maxSize` enforcement and scale tests (500+ files, 5MB logs)
12. **Sensitive-data leakage tests** — canary tokens in secrets/passwords/ConfigMaps verified absent from all output
13. **Performance benchmark** — wall-clock regression gate (<10s) with per-step latency checks

Step 15 is a final integration gate ensuring everything builds and passes together.
